# Установка на Windows

Renga–Codex Bridge — независимый локальный MCP-сервер. Codex превращает задание
в вызовы инструментов; мост выполняет заявленные операции через официальный COM
API. Отдельный ИИ-сервис и дополнительный ключ OpenAI API не нужны.
Подтверждённое покрытие и версии приведены в [CAPABILITIES.md](CAPABILITIES.md).

## Что установить самостоятельно

- Windows x64 и Python 3.11 или новее, x64. Проверенная локальная базовая среда:
  Python 3.12. Дополнительные версии в CI подтверждают тесты без Renga, а не COM.
- Renga с работоспособной лицензией и зарегистрированным COM API.
- Совместимый [SDK Renga](https://rengabim.com/sdk/), распакованный вне публичного
  репозитория. Нужна корневая папка с `tlb/RengaCOMAPI.tlb` и
  `C++/Include/Renga/EntityTypes.h`, `Parameters.h`, `Quantities.h`.
- Codex и, для автоматической регистрации, команда `codex` в PATH.

Установщик не скачивает и не устанавливает Renga, SDK, Python или Codex, не
меняет лицензирование и не запускает регистрацию Renga от администратора.

## Быстрый запуск

В PowerShell откройте локальный клон репозитория. Выберите отдельную пустую папку
для испытаний. Не указывайте папку рабочих архитектурных проектов.

```powershell
git clone https://github.com/ucrdaniel/Renga-Codex.git Renga-Codex-Bridge
Set-Location .\Renga-Codex-Bridge
.\scripts\install.ps1 -SdkPath 'C:\RengaSDK'
```

Если Python не найден автоматически:

```powershell
.\scripts\install.ps1 -PythonExe 'C:\Python312\python.exe' `
    -SdkPath 'C:\RengaSDK' -WriteRoot 'C:\Renga-tests\bridge'
```

По умолчанию разрешённая папка записи — `runtime/test-projects` внутри клона.
`-WriteRoot` переопределяет её; переменная `RENGA_BRIDGE_WRITE_ROOT` также
поддерживается. Дополнительные правила рабочего каталога Codex могут ограничить
запись ещё сильнее. Чтение сохранённого файла не даёт разрешение его менять.

Если локальная политика выполнения блокирует `.ps1`, запустите проверенный
скрипт однократно в отдельном процессе:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 `
    -SdkPath 'C:\RengaSDK'
```

Эта команда не меняет постоянную политику выполнения. Установщик проверяет Windows
и Python, структуру SDK, создаёт `.venv`, устанавливает собственный пакет и
зависимости, выполняет `pip check` и `doctor`. Диагностика открывает отдельный
принадлежащий мосту COM-процесс и показывает фактическую версию Renga. Пользовательский
проект не открывается и BIM-модель не изменяется.

Перед `codex mcp add` создаётся копия существующего `config.toml` с проверкой
SHA-256. Она сохраняется в `runtime/backups`; храните её приватно, поскольку
конфигурация может содержать секреты. Остальные MCP-серверы не удаляются.
Если имя уже принадлежит другой команде, установка откажется его заменять.
Используйте другое `-ServerName` либо осознанно передайте
`-ReplaceExistingRegistration`. Без CLI используйте `-SkipCodex` и регистрацию ниже.

## Подключение Codex

Установщик регистрирует `renga-codex-bridge` через локальный stdio. Команда запуска
указывает на Python этого клона; SDK и разрешённая папка передаются только процессу
моста. Пользовательские переменные среды Windows не создаются.

После установки переподключите MCP или откройте новый чат Codex. Попросите:
«Проверь состояние Renga через renga-codex-bridge, затем покажи фактически
проверенные возможности». `doctor` и чтение записи конфигурации ещё не доказывают,
что старый открытый чат обновил каталог инструментов.

Если CLI доступен позже, сначала самостоятельно скопируйте `config.toml`, затем
выполните команду из вывода установщика. Для ручной настройки без CLI можно добавить
этот фрагмент в **сохранённую резервную копией** конфигурацию, заменив пути:

```toml
[mcp_servers.renga-codex-bridge]
command = 'C:\Renga-Codex-Bridge\.venv\Scripts\python.exe'
args = ["-m", "renga_codex_bridge.mcp_server"]
startup_timeout_sec = 30
tool_timeout_sec = 240

[mcp_servers.renga-codex-bridge.env]
RENGA_SDK_PATH = 'C:\RengaSDK'
RENGA_BRIDGE_WRITE_ROOT = 'C:\Renga-tests\bridge'
PYTHONUTF8 = "1"
PYTHONIOENCODING = "utf-8"
```

Конфигурация находится в `$CODEX_HOME/config.toml`, если `CODEX_HOME` задан,
иначе в `%USERPROFILE%/.codex/config.toml`. Синтаксис регистрации и поля stdio:
[официальная документация Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

## Проверки и первый проект

Из этой же папки:

```powershell
$env:RENGA_SDK_PATH = 'C:\RengaSDK'
$env:RENGA_BRIDGE_WRITE_ROOT = 'C:\Renga-tests\bridge'
.\.venv\Scripts\renga-bridge.exe doctor
.\.venv\Scripts\python.exe -m pip check
```

Для разработки установите тестовые зависимости и выполните безопасные тесты:

```powershell
.\.venv\Scripts\python.exe -m pip install -e '.[test]'
.\.venv\Scripts\python.exe -m pytest -m 'not integration' -q
```

Настоящий COM/MCP end-to-end сценарий запускается отдельно по
[README](../README.md) и инструкции к тесту. Он должен создать новый тестовый
файл, изменить его, закрыть, открыть и проверить реальные сохранённые значения.
Используйте уникальное имя. Успешные unit-тесты не заменяют такой сценарий.

Для задания Codex укажите: точные размеры в миллиметрах, новый файл внутри
разрешённой папки, необходимость предварительного JSON-плана и проверки после
повторного открытия. Для настоящего заполнения проёма сначала выберите существующий
стиль: стиль по умолчанию может создать только отверстие.

После обновления до 0.2 переподключите MCP: сервер предоставляет 21 инструмент.
`bridge_create_levels_project` создаёт новый `.rnp` с заданными уровнями и
необязательной ортогональной сеткой осей через официальный IFC-импорт. Для этой
операции должны работать импорт и экспорт IFC в установленной Renga. Новые
файлы и промежуточные IFC сохраняются только в разрешённой папке. Существующий
проект этим способом не дополняется; прямое изменение отметки уровня остаётся
ограниченным. Формат запроса описан в [OPERATION_PLANS.md](OPERATION_PLANS.md).

Действие плана `room_marker` перемещает встроенный маркер помещения по глобальным
XY в миллиметрах. Оно не создаёт отдельный Tag и не заменяет ассоциативные размеры.

## Ошибки, перенос и удаление

| Ситуация | Действие |
|---|---|
| SDK не найден | Укажите корень SDK, а не `Docs`, `Net` или `tlb` |
| COM не зарегистрирован / Renga не запускается | Проверьте обычный запуск и установку Renga; используйте способ восстановления производителя |
| Python другого компьютера | Повторите установку; негодная `.venv` сохраняется в локальной резервной папке |
| MCP не появился в чате | Проверьте `codex mcp get renga-codex-bridge`, затем переподключите клиента |
| Отказ записи | Выберите файл внутри тестовой папки, проверьте её разрешения и дополнительные правила рабочего проекта |
| Тайм-аут / сбой | Изучите журнал и сохранённый файл перед повтором; не завершайте постороннюю Renga |

При переносе клона повторите установку с новыми абсолютными путями. Виртуальное
окружение и локальная запись MCP не являются переносимыми.

Удаление интеграции:

```powershell
.\scripts\uninstall.ps1
```

Удаляется только зарегистрированная этим клоном MCP-запись после проверки её
команды и резервного копирования конфигурации. Renga, SDK, остальные настройки,
репозиторий, `.venv`, модели и журналы остаются. Если `CODEX_HOME` изменился или
запись теперь принадлежит другой команде, скрипт откажется удалять её. Для ручной
регистрации проверьте путь в записи перед `codex mcp remove`.
